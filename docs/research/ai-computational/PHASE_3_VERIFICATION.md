## Reference and gate
Use existing independently coded fuzzy_reference_oracle.py, unchanged. Compare rounded centroid tolerance 0.00015, selected fuzzy output, fired-rule count, valid/distinct rule IDs, nonzero coverage and resolved action/target (separate from selected output). Rule-Based expected values derive from the frozen threshold specification and ordered prerequisite/next-target fixture. Record rule reason as well. This is specification conformance and numerical verification, not expert correctness. The oracle shares the algorithm specification; it is not an independent pedagogical gold standard. Compare count of fired rules (not exact per-rule identity against oracle); report distinct actual IDs. Fuzzy rounding near ties can cause discrepancies: report failures, never tune production code to pass. All six verification checks and engine successes must meet the defined gate; replay manifest must match. No silently discarded failures.
